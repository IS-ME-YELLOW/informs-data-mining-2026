# v2.4：v1.5.6 特征上的 XGBoost 分量基线

日期：2026-09-11。

本版沿用 v2.2 的“分别预测 P/N/D/R，再按官方公式合成 OSI”路线，把特征更新为 v1.5.6 的 163 列，并直接读取 `versions/v1.9_xgboost/` 中的 v1.9 元数据作为同族直接 OSI 对照。XGBoost 上限最终设为 8,000，早停耐心 100。

## 合成 OSI 的池化 OOF 结果

| Horizon | RMSE | MAE | RMSE 相对 v1.9 | MAE 相对 v1.9 |
|---|---:|---:|---:|---:|
| t+1h | 0.012039 | 0.003411 | -0.04% | -2.51% |
| t+6h | 0.010658 | 0.003221 | -0.02% | -1.22% |
| t+24h | 0.008580 | 0.002642 | -1.52% | -2.61% |
| t+48h | 0.007858 | 0.002070 | -0.86% | -2.48% |

四个 MAE 均改善；t+24/t+48 的 RMSE 改善较明确，t+1/t+6 仅近似持平。相对旧 v2.2，RMSE 变化为 `+0.81% / -0.25% / -1.00% / +0.08%`，因此不能把全部变化解释为特征升级的普遍收益。

80 个折中 13 个最佳轮数达到或超过 2,000，2 个超过 3,900，最大为 4,635。初始 4,000 上限下，t+1/P_t/fold4 的最佳轮数到 3,990；提高到 8,000 后在 4,263 正常早停，另有 t+24/P_t/fold2 在 4,635 正常早停。因此分量 XGBoost 的 8,000 上限是必要的，且本次没有折接近新上限。

新增列在分量任务中使用更明显，例如 `gust_gt30_frac_next_24h` 是 t+48/P_t 的第 1 特征，`tp_rate_next_1h` 是 t+1/N_t 的第 1 特征，`pct_forest_classified` 是 t+48/R_t 的第 1 特征。

## 复现与产物

```powershell
python -u versions/v2/v2.4/run_xgboost.py
python -u versions/v2/verify_v2_artifacts.py v2.4
```

本目录包含 16 个 JSON 最终模型、分量与 OSI 的 OOF/逐折/汇总指标、测试分量预测、特征重要性、提交、输入哈希元数据和 `verification.json`。16 个模型已全部重载并逐值复算通过。
