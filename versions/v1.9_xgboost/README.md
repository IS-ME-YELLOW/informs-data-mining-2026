# v1.9：v1.5.6 特征上的直接 OSI XGBoost 基线

> 合并远端同名 v1.9（分量专用 LightGBM）后，本实验目录改为 `v1.9_xgboost`；模型与产物内部的原始版本标识 `v1.9` 保持不变。

日期：2026-09-11。

本版保留 v1.6 的 XGBoost 参数、`balanced_v1` 县级五折、seed=42、Huber 目标和 OSI 后处理，将输入从有已知错误的 v1.5.2 141 列缓存更新为冻结的 v1.5.6 163 列缓存。最大轮数由 2,000 提高到 4,000，早停耐心保持 100。

## 池化 OOF 结果

| Horizon | RMSE | MAE | 五折最佳轮数 | 全量轮数 |
|---|---:|---:|---|---:|
| t+1h | 0.012044 | 0.003498 | 987 / 284 / 1827 / 1607 / 2037 | 1348 |
| t+6h | 0.010661 | 0.003261 | 736 / 551 / 1465 / 932 / 2641 | 1265 |
| t+24h | 0.008713 | 0.002713 | 542 / 535 / 1869 / 170 / 1894 | 1002 |
| t+48h | 0.007926 | 0.002122 | 378 / 136 / 969 / 98 / 135 | 343 |

相对旧 v1.6，RMSE 变化为 `+1.21% / +0.05% / -0.22% / -0.20%`，不是四个 horizon 一致改善。新特征中 `gust_gt30_frac_next_48h` 在 t+6 排第 5，`tp_rate_next_24h` 在 t+24 排第 9，`pct_forest_classified` 在 t+48 排第 9，说明新增列确实被模型使用，但收益受 horizon 影响。

20 个折中有 2 个最佳轮数超过 2,000，最大为 2,641；没有折接近 4,000。提高上限修复了旧版潜在截断，4,000 对直接 XGBoost 已足够。

## 复现与产物

```powershell
python versions/v1.9_xgboost/run_xgboost.py
python -u versions/verify_gbdt_artifacts.py v1.9_xgboost
```

本目录包含 4 个 JSON 最终模型、完整 OOF、逐折和汇总指标、特征重要性、提交文件、输入哈希元数据及 `verification.json`。校验已重载四个模型，复算 OOF 指标，并确认提交值、标识列和尾部 NaN 掩码一致。
