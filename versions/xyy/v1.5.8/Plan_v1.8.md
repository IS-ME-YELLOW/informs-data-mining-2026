# v1.8 构建方案：v1.5.6 特征上的 P/N/D/R 分量 LightGBM

## 1. 目标

v1.8 检验一个单独的问题：在完全相同的数据、特征、县级交叉验证和 LightGBM 配置下，先预测 `P_t/N_t/D_t/R_t` 再按官方公式重组 OSI，是否比直接预测 OSI 更稳、更准。

本版不增加任何特征。模型输入固定为 v1.5.6 的 163 列特征。这里的“暂不引入未来天气特征”指不加入 v1.5.7 的 F1 目标时刻天气轨迹，也不开发新的未来天气特征；v1.5.6 已有的基础气象窗口及窗口质量列作为冻结基线的一部分原样保留。

## 2. 固定协议

- 特征：`cache/features_*_v1.5.6.parquet`，163 列。
- 官方 OSI 标签：`cache/targets_train_v1.5.6.parquet`。
- 分量标签：从 `data/DM_Train.csv` 中按县、按时间将 P/N/D/R 分别向未来 1、6、24、48 小时平移。
- 交叉验证：`cv/cv_assignments_balanced_v1_seed42.csv`，5 折，县级分组，seed=42。
- LightGBM：复用 phase1 的 Huber 参数、2,000 轮上限、100 轮早停。
- 最终训练轮数：五折 `best_iteration` 的算术平均后向下取整，与 phase1 实现一致。
- 分量预测：每个分量先裁剪到 `[0, 1]`。
- OSI 重组：`max(0, 0.40P + 0.35N + 0.25D - 0.10R)`。
- OSI 后处理：裁剪到 `[0, 0.65]`，小于 `0.001` 置零。
- 主指标：逐 horizon 的池化 OOF RMSE；MAE、折间标准差和县级 bootstrap 为辅助诊断。

## 3. 对照组

| 编号 | 方法 | 作用 |
|---|---|---|
| C0 | 直接回归 OSI 的 4 个 LightGBM | v1.5.6 同协议基线 |
| C1 | 16 个 P/N/D/R LightGBM，逐 horizon 重组 OSI | 检验分量监督是否有效 |
| C2 | C0 与 C1 原始 OSI 预测等权平均，之后统一后处理 | 检验两类模型误差是否互补 |
| C3 | 对同一县、同一目标小时的各 horizon 分量预测先等权平均，再重组 OSI | 检验“同一目标小时只产生一个分量预测” |

C3 只使用模型预测，不使用标签决定权重。对目标小时 `s`，可用候选来自所有满足 `s=t+h` 的 horizon；先分别平均 P、N、D、R，再按官方公式计算唯一 OSI，并映射回提交表的四个 horizon 单元格。

## 4. 训练与保存

1. 校验 v1.5.6 特征、目标、元信息、固定折和原始数据的键。
2. 构建分量标签，检查缺失掩码与官方 OSI 标签完全一致。
3. 检查由真实分量重组的 OSI 与官方标签最大绝对误差不超过 `5.1e-5`。
4. 训练 C0 的 4 个直接模型和 C1 的 16 个分量模型。
5. 保存每个交叉验证折模型及 20 个全量最终模型，记录哈希和训练轮数。
6. 生成 C0/C1/C2/C3 的 OOF 预测、测试预测和提交文件。
7. 重新加载保存模型，复算预测并核对组合公式、C3 唯一目标约束、提交尾部 NaN 和文件哈希。

## 5. 诊断产物

- 总体、逐折、逐县 RMSE/MAE。
- 县级 paired bootstrap：报告差值、95% 区间和改善概率。
- C0 与 C1 的误差相关系数。
- 按真实 OSI 强度区间和目标日期分组的误差。
- P/N/D/R 各自的预测误差，以及各分量误差对最终 OSI 误差的贡献。
- 20 个最终模型的特征重要性。

## 6. 决策规则

- C1 若在大多数 horizon 上优于 C0，且 bootstrap 方向较稳定，则分量路线进入下一阶段。
- C2 若稳定优于 C0 和 C1，说明两类监督形成了可用的模型多样性，可作为新的组合基线。
- C3 若优于 C1，说明目标小时一致化对分量路线有效；若退化，则保留逐 horizon 分量模型，不继续增加时序门控复杂度。
- 单个固定五折上的极小差异不直接视为确定提升；结合县级 bootstrap、折方向和误差相关性判断。

## 7. 文件边界

代码、模型、指标、预测、提交、运行元数据、验证结果和报告全部写入 `versions/v1.8/`。只读复用 v1.5.6 缓存、原始数据、固定 CV 清单和 phase1 参数；不覆盖历史版本资产。
