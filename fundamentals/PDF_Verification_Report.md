## 二、不通过的论断(7项,详细分析)

### FAIL 1: OSI公式 — 38,170行"不匹配" ⚠️ 精度伪影,非真实错误

| | 值 |
|---|---|
| PDF论断 | OSI = 0.40·P_t + 0.35·N_t + 0.25·D_t − 0.10·R_t (clip≥0) |
| 实际 | 38,170 / 51,624 行 (74%) 用存储组件重算后与 osi 列不完全一致 |
| 差异范围 | min=0.000001, max=**0.000050**, mean=0.000024 |
| **结论** | **非真实错误,是精度伪影**。osi 列存储为 4 位小数(如0.0001, 0.0008),组件列存储为 ~8 位小数。用舍入后的组件重算 OSI 会产生微小差异。公式本身正确。 |

**额外发现 — N_t 与 R_t 非互斥**:
- PDF定义: N_t = max(0, ΔoutageCount)/ct, R_t = max(0, −ΔoutageCount)/ct → 数学上互斥(一个为0时另一个才非0)
- 实际数据: **26.8% 的行 N_t > 0 且 R_t > 0 同时成立**
- 例: FIPS 18009 在3/12 10:00, outageCount 从10变到10(Δ=0), 但 N_t=0.000306, R_t=0.000306 都非零
- **推测**: 实际存储的 N_t/R_t 可能是"毛流量"(新增停电数/恢复数分别计), 而非PDF所述的"净变化"定义。在真实电网中,同一小时内可以既有新停电又有恢复。
- **对建模的影响**: OSI 公式仍与存储的组件值一致(精度内),测试集重建 OSI 时**直接用存储的 P_t, N_t, D_t, R_t 代入公式即可**,无需从 outageCount 重新推导 N_t/R_t。


### FAIL 3: osi_target_t01h 最大值 0.599 vs 0.6505 ❌ PDF有误

| | 值 |
|---|---|
| PDF论断 | Range: 0–0.599 |
| 实际 | max = **0.6505** |
| 对比 | osi max = 0.6505(吻合), t06h max = 0.5989(≈PDF的0.599), t48h max = 0.5980(≈PDF的0.598) |
| **结论** | **PDF对 t01h 的 max 有误**。实际 0.6505 恰好等于 osi 本身的 max,合理(t01h = 下一小时的 osi)。t06h/t48h 的 max 与 PDF 吻合,只有 t01h 不符。PDF可能用了不同版本数据或笔误。 |

### FAIL 4: osi_delta_t01h 范围 ❌ PDF疑似复制了 t06h 的值

| | 值 |
|---|---|
| PDF论断 | Range: −0.369 ~ 0.596 |
| 实际 | **−0.1757 ~ 0.2926** |
| 对比 | delta_t06h 实际: −0.3692 ~ 0.5963(**与PDF给delta_t01h的范围完全吻合**) |
| **结论** | **PDF疑似将 delta_t06h 的范围复制粘贴给了 delta_t01h**。delta_t01h(1小时变化)的范围理应比 delta_t06h(6小时变化)更窄,实际数据证实了这一点。 |

### FAIL 5: FIPS 18111 预事件100%停电 ⚠️ 检查条件过严,PDF论断基本正确

| | 值 |
|---|---|
| PDF论断 | "one county, FIPS 18111, shows 100% outage rate in the pre-event window" |
| 实际 | FIPS 18111 (Newton County, IN) 预事件 48 小时中: **前 5 小时(3/11 0:00–4:00) outage_pct=100%**,之后降至 90.59% → 77.42% → ... → 2.42% |
| 100%的小时数 | 5 / 48 |
| 全部302县中预事件达到100%的县 | 仅 FIPS 18111 (1个县, 与PDF一致) |
| **结论** | **PDF论断基本正确**。"shows 100% outage rate"可理解为"出现过100%", 非须全程100%。FIPS 18111 确实是唯一在预事件中达到100%的县。我的验证脚本检查条件过严(要求所有48小时都=100%)。 |

### FAIL 6: 预事件停电县数 236 vs 237 ⚠️ 差1,可能数据版本差异

| | 值 |
|---|---|
| PDF论断 | "236 of 239 train counties" 有2月遗留停电 |
| 实际 | **237** / 239 有预事件停电 |
| 预事件无停电的县 | FIPS 42023 (Cameron County, PA), FIPS 42057 (Fulton County, PA) |
| **结论** | **差1个县**。可能是数据版本差异或计数口径不同。影响不大。 |

### FAIL 7: countyName 唯一性 187 vs 224 ⚠️ PDF的187仅对应训练集

| | 值 |
|---|---|
| PDF论断 | "187 unique names across 302 counties (some repeat across states)" |
| 实际 | 训练集(239县)唯一名: **187**(与PDF吻合); 测试集(63县)唯一名: 57; 全部302县唯一名: **224** |
| 重复县名 | 49个名称跨州重复(如"Franklin County"出现在IN/OH/PA三个州) |
| **结论** | **PDF的"187"仅对应训练集239县**,但PDF写的是"across 302 counties"。实际302县的唯一名称数为224。可能是PDF撰写时仅统计了训练集,或表述不精确。 |
