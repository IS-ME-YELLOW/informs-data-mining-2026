> **后续状态更新（2026-09-07）**：本文记录的是 v1.5.3 时点的审计。第 2、3、5 项所述的评估问题已在 v1.5.4 中修复：OOF 现采用和提交相同的裁剪/置零路径，均值基线只用折内训练行，且使用固定 `balanced_v1` 县级五折。v1.6 XGBoost 与 v1.7 CatBoost 已完成直接 OSI 回归；v2.1/v2.2/v2.3 也已完成“分别预测 P/N/D/R 后合成 OSI”。这些仍不是下文定义的“非零分类器 + 正值条件回归器”两阶段模型。新结果与产物见 `Results.md` 和 `versions/v2/`。

**结论**

`v1.5.3` 目前**没有实现两阶段预测**。它是 4 个独立的单阶段 LightGBM Huber 回归器，加上测试预测阶段的硬阈值截断：

```text
X -> LightGBM 回归 OSI -> clip [0, 0.65] -> pred < 0.001 设为 0
```

这不是：

```text
X -> 分类器 P(OSI > 0)
X -> 仅正样本训练的回归器 E[OSI | OSI > 0]
预测 = P(OSI > 0) * E[OSI | OSI > 0]
```

**主要发现**

1. 两阶段所需的分类器不存在。  
[model.py](/D:/INFORMS%20Data%20Mining%20Challenge%20Details/code_phase1/model.py:29) 的 `train_one_horizon` 只接收连续 `y_col` 并训练一个 LightGBM；[config.py](/D:/INFORMS%20Data%20Mining%20Challenge%20Details/code_phase1/config.py:72) 也只有 `objective='huber'`。代码中没有 `is_nonzero` 标签、`objective='binary'`、`predict_proba`，也没有“只拿正样本训练回归器”的逻辑。

2. 当前的 `post_process` 是启发式后处理，且未通过 CV 验证。  
[main.py](/D:/INFORMS%20Data%20Mining%20Challenge%20Details/code_phase1/main.py:117) 只对**测试集**预测调用 `post_process`；[evaluate.py](/D:/INFORMS%20Data%20Mining%20Challenge%20Details/code_phase1/evaluate.py:70) 固定把小于 `0.001` 的值置零。  
但 OOF/验证集指标是在截断前计算的，所以日志中的 RMSE/MAE 并不代表最终提交文件的 RMSE/MAE。注释中“改善零预测偏差”目前没有 OOF 证据支持。

3. 裁剪也未进入 CV 指标。  
[model.py](/D:/INFORMS%20Data%20Mining%20Challenge%20Details/code_phase1/model.py:135) 的 `[0, 0.65]` 裁剪仅在测试推理调用；验证阶段的 `pred_val` 直接计算指标。因此 CV 与最终预测还有第二处行为不一致。

4. OOF 已生成，但没有被用于两阶段决策。  
[model.py](/D:/INFORMS%20Data%20Mining%20Challenge%20Details/code_phase1/model.py:45) 会存 OOF；但 [main.py](/D:/INFORMS%20Data%20Mining%20Challenge%20Details/code_phase1/main.py:106) 训练后只记录原始回归指标，没有用 OOF 来选择零阈值、检验置零是否有效，或学习融合权重。

5. 次要问题：均值基线有验证集信息泄漏。  
[mean_baseline](/D:/INFORMS%20Data%20Mining%20Challenge%20Details/code_phase1/evaluate.py:41) 用整个 `y` 计算均值，再在各验证折打分；正确做法应当每一折只用该折训练县的目标均值。这不影响 LightGBM 本身，但会令 Mean baseline 略乐观。

**现有模型表现的解读**

日志显示 1.5.3 的单阶段模型已明显优于零基线，例如 `t+48h` 的 CV RMSE 为 `0.007378`，零基线为 `0.009148`。因此两阶段模型应视为一个有风险的对照实验，而不是默认替换当前模型。尤其若评分是 RMSE，概率乘积是更自然的连续预测；把结果硬切为零未必改善 RMSE。

**建议的两阶段实现标准**

每个 horizon 独立训练 2 个模型，共 8 个模型：

```text
z_h = 1[OSI_target_h > 0]

分类器：X -> P(z_h = 1)
回归器：X[z_h = 1] -> E[OSI_target_h | z_h = 1]
最终预测：p_nonzero * positive_regression
```

必须在现有按 `fipsCode` 分组的每个 CV 折内完成分类器、正样本回归器和预测，汇总 OOF 后比较：

- 单阶段原始预测
- 单阶段预测后阈值置零
- 两阶段概率乘积
- 两阶段硬路由，如 `p >= τ` 才保留回归值

阈值 `τ`、零标签是否使用 `>0` 或小的 epsilon，都只能依据训练折/OOF 选择，且应按 horizon 分别选择。这样才能判断两阶段是否确实带来跨县泛化增益。

## 
3. 如何看待当前 CV 波动
波动确实较大，但不等于模型必然过拟合。1.5.3 中：
- t+1h：0.0086--0.0194
- t+48h：0.0049--0.0126
而且 fold 1 在短 horizon 最难、fold 3 在长 horizon 最难。这说明不同县群在不同风暴阶段的机制不同，而不只是训练随机性。
更重要的是，v1 到 v1.5.3 的平均 RMSE 改善通常只有 0.0001--0.0005 量级，明显小于折间标准差。因此不能依据一次 5 折均值的微小变化宣布某特征或模型胜出。
建议：
- 固定当前 seed=42 的 5 折，作为日常快速比较基准。
- 对进入候选集的版本，再做多 seed 的重复 Stratified Group CV。
- 保存 OOF 后按“县”聚合误差，比较两个模型在相同县上的误差差值，并对县做 paired bootstrap CI。
- 分析最差折的州、静态暴露、零值率、强风暴时段与高 OSI 县占比。
- 只有在多数重复切分均获益、且增益超过不确定性时，才采纳新模型或特征组。
第 9 篇的核心启示也是这个：性能不仅随样本量变，还随“训练事件是否代表待测事件”变。你们不能增加独立风暴事件，但可以量化“县切分敏感性”，并避免在单一切分上反复调参。

## 线性模型加入
4. GLM/GAM 可以怎样利用
不建议把 Poisson/负二项 GLM 原样用于 OSI。它们适合非负整数计数，而 OSI 是连续、零膨胀、且有上界的指数。
更合适的定位有两个：
- 可解释对照模型：用少量预先选定且低共线的变量做 GAM，例如 s(gust_max_48h)、s(total_tp_48h)、s(t2m)、s(soil_moist)、森林/树冠暴露及少量交互。它可用于检查 LightGBM 是否学出反物理形状。
- 极端值保护模型：对风速采用单调样条或单调约束，和 LightGBM 做 OOF 融合。GAM 在极端区间不一定更准，但不会像树模型那样在训练边界后完全变平。
一个比完整 GAM 更低成本的实验是：
- LightGBM 尝试 objective='tweedie'，它适合带零的非负连续目标。
- 用 TweedieRegressor 或 spline GAM 做 5--10 个特征的低容量对照。
- 只依据县级 OOF 学习 LightGBM 与 GAM 的非负融合权重。

## 11：
模型顺序应是：LightGBM -> 多树模型 OOF 融合 -> 低容量 GRU -> 必要时 GAM/Tweedie 稳健性模型，而不是先上 CNN、图网络或 RL。

## 13：风雪特征
尚可考虑的仅是小规模、机制明确的消融组，而不是再铺一批特征：
- 风雪共现：强风时段内的 csnow 占未来窗口总 csnow 的比例，或 sum(csnow * I(gust > threshold))。
- 近冰点湿冷风险：tp 与“温度接近 0 C、湿度高”的共同暴露时长。
- 植被-冬季天气交互：pct_forest × snow_exposure 或 tree_canopy × snow_exposure。

## 13-模型学不到极端值？
- 训练/测试在可用静态特征上的 KS 检验没有明显分布差异，降低了 OOD 风险，但不能证明不存在“强风、森林、前期停电”组合上的 OOD。
- 当前代码把预测裁剪到训练观测最大值 0.65。0.65 是经验最大值，不是 OSI 的物理上限；若测试存在更极端县，这个裁剪会强制低估。应把它视作一个需要 OOF 和物理范围共同审视的保护措施，而不是天然正确的边界。
